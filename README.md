# 哪儿见 MeetSomewhere

朋友聚餐的多人地点协商微信小程序。第一版实现聚会创建与邀请、成员条件填写、手动添加餐厅、逐点评价、组织者比较与定案、成员最终参加确认。

## 技术栈

- **微信原生小程序 JavaScript / WXML / WXSS**：仓库原本只有需求文档。原生页面不依赖前端构建器，微信开发者工具可直接打开；页面、公共工具与云函数分目录维护。
- **微信云开发（云数据库 + 云函数）**：多人共享数据由云函数统一校验角色；出发地、散场后目的地和个人限制保存在独立成员记录中，客户端只能通过云函数取得按授权筛选的结果。
- **腾讯位置服务 WebService**：路线请求在云函数发出，Key 只放在云函数环境变量中。公交/地铁、驾车、步行可分别估算；“较快路线”比较公交与驾车。去程取聚会开始前一小时为估算出发时刻，回程取预计散场时刻。实际效果需用目标城市和正式 Key 验证。

## 运行与部署

1. 在微信公众平台注册小程序并开通云开发，在微信开发者工具中打开项目根目录。确认 `project.config.json` 中的 AppID 属于当前小程序，并已关联所用云环境。
2. 在 `miniprogram/config.js` 填写 `cloudEnvId`。云环境 ID 用于连接环境，不是服务密钥；腾讯地图 Key 只放云函数环境变量。不要把 Key 写进小程序代码。
3. 在同一个云环境的**云开发 → 数据库（文档型数据库）→ 新建集合**中，逐个创建 `meetings`、`profiles`、`candidates`、`ratings`、`routeSummaries`，名称大小写必须一致；新建空集合即可，无需手动添加字段或数据。**五个集合的数据权限都设为“仅管理端可读写”**，或将自定义规则设为 `{ "read": false, "write": false }`。小程序端不能直接读写，页面只调用 `api` 云函数。
4. **先在开发者工具左侧文件树右键 `cloudfunctions` 根目录**，通过“当前环境”或“选择想要上传的目标环境”选中 `config.js` 中填写的云环境。看到根目录旁显示环境名后，再分别右键 `cloudfunctions/api` 和 `cloudfunctions/cleanup`，执行“上传并部署：云端安装依赖”。推荐 Node.js 20 运行时。`api` 函数超时时间建议设为 **60 秒**，用于一次更新多位成员的路线。
5. 为 `cleanup` 上传 `config.json` 的定时触发器；该配置每 30 分钟清理已到预计散场时间的聚会。应用端访问过期聚会时也会立即清理。
   在云函数权限控制中允许已登录微信用户调用 `api`，禁止客户端调用 `cleanup`；定时触发器仍可运行。
6. 在腾讯位置服务控制台创建启用 WebServiceAPI 的 Key，并在 **`api` 云函数环境变量**设置 `TENCENT_MAP_KEY`。不要写入代码、小程序配置或仓库。确认云函数网络可访问 `apis.map.qq.com`，并在控制台核对路线接口权限、额度、费用及安全限制。
7. 编译小程序。组织者创建聚会后用页面右上角分享入口邀请朋友；受邀者输入称呼加入。没有 Key 时仍可走协商流程，路线会明确显示为未计算。

### 遇到 `FUNCTION_NOT_FOUND` / `-501000`

小程序固定调用名为 `api` 的云函数。先核对 `miniprogram/config.js` 的 `cloudEnvId`，并在开发者工具**右键 `cloudfunctions` 根目录选择该环境**；只填写 `wx.cloud.init({ env })` 不会替编辑器选择云函数的部署目标。再右键 `cloudfunctions/api`，选择“上传并部署：云端安装依赖”。等待部署成功后，在该环境的云函数列表确认存在 **`api`**（名称区分大小写），然后重新编译小程序。`cleanup` 是结束后清理数据的定时函数，也需要单独部署；但它缺失不会导致首页的 `api` 调用报错。若云端已有 `api`，优先检查是否部署到了另一个环境，或当前小程序 AppID 未关联此环境。参见[腾讯云函数部署指引](https://cloud.tencent.com/document/practice/583/30936)与[小程序调用部署步骤](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。

### 遇到 `DATABASE_COLLECTION_NOT_EXIST` / `-502005`

说明云函数已经开始执行，但当前云环境里缺少报错所指的文档集合。按第 3 步一次创建上述五个空集合并设置权限；无需重新部署 `api`，重新编译或刷新小程序后再试。腾讯云的[文档型数据库说明](https://docs.cloudbase.net/database/introduce)列出了开发者工具中“云开发 → 数据库 → 新建集合”的入口。

## 数据与隐私规则

- 出发地与散场后目的地各自默认“仅用于路线计算”。选择“仅组织者可见”或“本次成员可见”后，授权对象才可看到地点名称；未授权的位置、坐标和限制原文不会出现在聚会汇总中。
- 组织者只看到意向分布、预算人数、匿名路线统计、硬性冲突及待确认人数；看不到个人限制原文或未授权位置。完整往返路线少于三人时，不显示可推断个人行程的时长统计。
- 未填写、未评价、还没看过、路线未知和“可以接受”分别保留；路线未知不当作零分钟。硬性冲突先于各排序视角处理，一般偏好与地点意向不会抵消硬性冲突。
- 成员修改位置、出行方式、限制，或组织者修改聚会时间后，路线摘要会失效，需组织者在比较台逐店更新。路线更新时间与估算属性会显示。
- 组织者手动结束聚会，或到达预计散场时间后，精确起终点、个人限制和路线摘要会被清除；本次位置授权不继承到下一场聚会。最终确认与此前的地点意向独立。

## 当前需要外部配置或验证

- 真机、多人云端和真实路线联调需要已部署的云函数、数据库与腾讯位置服务 Key；仓库不保存 Key。
- 首发城市、腾讯路线接口配额与商用要求、未来散场时段的公交质量和地图坐标精度，需配置真实环境后验证。
- 第一版不做自动搜店、历史推荐、自定义权重或订阅消息推送。成员通过重新进入聚会查看定案；当前分享入口用于邀请。
- 正式上线前需在小程序平台完成隐私协议、地图服务商数据处理与保存期限说明，并确认数据库备份的删除周期。
