# 聚会地点小程序｜产品需求草案

版本：0.1（需求讨论稿）  
日期：2026-10-22

## 1. 产品概述

面向朋友聚餐场景，帮助组织者收集成员的时间、预算、出行路线与地点意向，快速比较候选餐厅并作出决定，减少群聊中的重复询问和信息遗漏。

产品提供决策信息与路线比较，最终由组织者定地点；成员对地点的意向评价不等于最终参加承诺。

## 2. 目标用户与角色

- **组织者**：创建聚会、邀请成员、维护候选地点、查看汇总与路线比较、确定地点。
- **成员**：加入聚会、填写个人条件、添加候选地点、评价地点、最终确认参加情况。

每场聚会的组织者与成员角色独立。

## 3. 第一版目标与范围

### 目标

1. 让成员低成本提交与决策有关的信息。
2. 让成员快速表达对候选餐厅的态度。
3. 让组织者看见意向、预算、可行性以及所有成员去程和回程的估算。
4. 让成员控制出发地和散场后目的地的公开范围。

### 第一版范围

- 聚焦朋友聚餐。
- 候选餐厅由组织者和成员手动添加。
- 接入真实地图路线服务，分别计算成员出发地到餐厅、餐厅到散场后目的地的路线。
- 位置默认“仅用于路线计算”；出发地与散场后目的地分别授权。
- 成员自行声明个人限制；组织者只看到作出决策所需的提示，不显示限制的敏感细节。
- 先交付需求与界面设计稿，不进入代码开发。

### 暂不纳入第一版

自动搜店/餐厅推荐、基于历史的个性化推荐、自定义权重公式、复杂多地点行程规划、活动类型扩展。

## 4. 核心流程

1. 组织者创建聚会：名称、日期/候选时间、预计散场时间、预算、成员邀请与截止时间。
2. 成员加入：填写可参加时间、出发地、散场后目的地、出行方式、预算、个人限制与偏好，并分别设置两个地点的可见性。
3. 添加候选餐厅：组织者和成员手动添加名称、位置、价格/人均范围、备注等。
4. 可行性整理：系统根据已提交时间、预算与行程限制提示冲突或缺失信息。
5. 地点评价：成员对每个候选选择“很想去 / 比较想去 / 可以接受 / 不太想去 / 不方便参加 / 还没看过”。
6. 组织者比较：查看意向分布、预算、硬性冲突、去程、回程和往返负担；切换排序视角。
7. 组织者定案：选择地点、填写简短说明。
8. 成员最终确认：单独确认参加与否。
9. 活动结束：关闭本次位置共享；精确位置不自动用于下一场聚会。

## 5. 功能需求

### 5.1 聚会创建与邀请

- 创建、编辑、关闭聚会。
- 设置日期/时间或候选时间段、预计散场时间、人均预算范围、回应截止时间。
- 生成微信分享入口/邀请卡。
- 展示已加入、未回应、信息未完成的人数。

### 5.2 成员信息

成员可提交：

- 可参加时段、最早可到时间、是否必须提前离开及时间。
- 出发地与散场后目的地，可使用地点搜索/地图选点；允许填大致区域。
- 去程/回程交通方式偏好。
- 人均预算范围。
- 必须满足的个人限制，以及一般偏好。
- 出发地与散场后目的地各自的可见范围。

限制由成员本人声明。组织者可看到决策所需的结果提示（如“此地点对一位成员存在回程可行性问题”），不显示其限制详情，除非成员主动公开。

### 5.3 地点管理

- 组织者和成员均可手动添加候选地点。
- 候选信息至少包括地点名称、地图位置、人均价格/范围；可选菜系、环境、备注及来源链接。
- 信息状态区分“已核实 / 待核实 / 未提供”。
- 后续可由组织者移除候选或标为不再考虑；不要求第一版自动检索餐厅。

### 5.4 地点评价

- 每人对每个候选提交一个状态：很想去、比较想去、可以接受、不太想去、不方便参加、还没看过。
- “还没看过”不能计作中立或接受。
- “不方便参加”和“不太想去”可选填原因类别：预算、距离、时间、口味/菜系、其他。
- 组织者默认看汇总分布；个人评分是否公开可作为后续单独决策项。

### 5.5 路线计算与比较

- 对每位成员及候选地点分别计算去程和回程，不把两段只合并为单一总分。
- 路线时间受路线服务商、交通方式、出发/散场时间和城市覆盖影响；页面标示估算属性与更新时间。
- 地点卡展示去程、回程、往返负担摘要；并列呈现平均/中位负担、最长个人负担、最长回程及成员间差距。
- 缺失路线显示“未提供/未计算”，不得作为 0 分钟。
- 系统提示路线限制冲突，但不向组织者暴露限制的敏感原因。
- 排序视角：大家意向优先、往返总时间较少、照顾最远成员、回程优先、成员路程更均衡、综合折中。
- 每种排序都展示解释，不使用不可解释的单一综合分数作为唯一结论。

### 5.6 定案与参加确认

- 组织者选定地点并可填写决定说明。
- 成员在地点确定后另行确认参加/不参加/待定。
- 地点评价不被解释为参加承诺。

## 6. 业务规则

- **硬限制先检查，偏好再排序。**个人无法满足的时间/回程约束不可被其他成员的高意向抵消。
- 成员未填写、未评价、未知路线均单独表示，不推断为接受或便利。
- 对于未知或不完整的餐厅信息，显示待核实提示。
- 预计散场时间是路线计算输入；若发生变化，应重新计算回程并更新提示。
- 位置授权按单场聚会生效；两个位置字段分别控制。
- 活动结束后关闭共享；是否长期保存常用地点需另行征得成员主动同意。

## 7. 隐私与数据展示

每个位置字段采用以下可见性：

1. **仅用于路线计算（默认）**：其他参与者看不到具体地点；路线结果按成员选择呈现个人值或仅参与匿名汇总。
2. **仅组织者可见**：组织者可以看到具体地点，其他成员看不到。
3. **公开给本次聚会成员**：本次成员可看到地点信息；仍可选择公开大致区域或精确 POI。

出发地和散场后目的地独立设置。成员可修改或删除位置；修改后路线结果更新。应向用户说明位置会被提交给所选地图服务用于路线估算，并在正式上线前明确存储期限、删除机制及服务商数据处理条款。

## 9. 待确认事项

- 首发服务城市/区域（影响地图路线质量验证）。
- 组织者可见的路线明细是仅展示时长，还是可看到个人起终点名称（成员授权后）。
- 匿名汇总的最小人数门槛，以及个人路线时长是否允许成员单独授权展示。
- 地点的“意向评价”默认是否匿名汇总。
- 预算冲突如何定义：由成员标为硬上限，还是只作为偏好范围。
- 组织者能否设置必须满足的聚会级条件（例如全体可参加时段），还是只由成员声明个人限制。
- 第一版要支持的路线方式优先级（建议公交/地铁与驾车，步行作为接驳；最终依据目标用户）。
