# 聚会地点小程序｜界面设计稿（文字线框）

版本：0.1（需求讨论稿）  
目标：以手机竖屏为主，优先保证参与者快速提交、快速投票，组织者能看懂多维取舍。

## 信息架构

- 首页：我参与的聚会、发起聚会
- 聚会详情：流程进度、时间、成员、地点、决策摘要
- 我的信息：时间、路线、预算、限制与偏好、隐私设置
- 候选地点：地点列表、地点详情、添加地点
- 地点评价：快速评价候选
- 组织者比较台：意向/预算/可行性/路线比较与排序视角
- 最终确认：地点与参加状态

## 页面 4：我的情况（分步表单）

步骤 A｜时间与预算

```text
你什么时候方便？
[周六 18:00 后] [周日午餐] [自选]
最晚需要几点离开？ [不需要 / 20:30]
人均预算 [100–200 元]
```

步骤 B｜出发地与出行方式

```text
从哪里出发？
[搜索地点/地铁站] [地图选点]
交通方式 [公交/地铁] [驾车] [按最方便路线]

谁能看到出发地？
● 仅用于路线计算（默认）
○ 仅组织者可见
○ 公开给本次聚会成员
```

步骤 C｜散场后去向（可跳过）

```text
散场后要去哪里？
[搜索地点/地铁站] [地图选点] [暂不确定]
预计离开时间 [21:30]
交通方式 [公交/地铁] [驾车] [按最方便路线]

谁能看到散场后目的地？
● 仅用于路线计算（默认）
○ 仅组织者可见
○ 公开给本次聚会成员
```

步骤 D｜限制与偏好

```text
必须满足（由你声明）
[＋ 添加：不能晚于 22:00 离开]
[＋ 添加饮食/行动/其他限制]

偏好（可选）
[菜系] [安静] [靠近地铁] [可接受排队]
```

提交前隐私预览：明确说明每个位置的公开范围、地图路线估算用途和可修改方式。组织者只会看到决策提示，不会看到未授权的限制细节。

## 页面 7：组织者比较台

```text
┌────────────────────────┐
│ 地点比较                 │
│ 排序：[综合折中 ▼]        │
│ 意向优先/省总时间/照顾最远 │
│ 回程优先/路程均衡          │
├────────────────────────┤
│ 巷口小馆       综合较稳    │
│ 意向 6 想去 · 1 接受 · 1 未评│
│ 预算 7 人符合 · 1 人未确认 │
│ 去程 约 28 分钟/人         │
│ 回程 约 34 分钟/人         │
│ 最长单程约 58 分钟         │
│ 提示：1 位成员回程可行性待确认│
│ [展开路线摘要]             │
├────────────────────────┤
│ 北岸火锅       意向最高    │
│ 意向 5 想去 · 3 接受       │
│ 去程较均衡；2 人回程较长   │
│ [展开路线摘要]             │
└────────────────────────┘
```

路线展开时按授权显示具体位置；未授权者只显示估算或匿名汇总。组织者不看到个人限制细节，只看到如“存在回程可行性问题”的提示。

排序切换后，页面显示“排序依据”说明，例如：“当前优先减少最长个人往返时间”。不提供无解释的单一总分。

## 页面 8：确定地点与最终确认

组织者选择地点：

```text
确定本次地点？
巷口小馆 · 周六 18:30
决定说明（可选）[回程更方便，预算也合适]
[确定并通知成员]
```

成员确认：

```text
地点已确定：巷口小馆
周六 18:30 · 人均约 120–160 元
[参加] [不参加] [待定]
```

## 页面 9：活动结束

显示活动摘要与“本次位置共享已关闭”。如希望保存常用地点或个人偏好，单独询问，不默认保存精确位置。

## 状态与异常文案

- 缺少路线：“有 2 位成员未提供路线，当前路线比较仅基于已提供信息。”
- 路线服务失败：“暂时无法获取路线，请稍后重试；本次数据不会被当作 0 分钟。”
- 时间冲突：“存在成员无法满足该时间安排，具体限制仅成员本人可见。”
- 回程风险：“有成员的回程可能受限，组织者可调整散场时间或选择其他地点。”
- 位置隐私：“其他参与者看不到具体起终点；位置用于本次路线估算。”
- 信息待核实：“价格/营业信息尚未确认。”

## 设计原则

- 参与者先看到需要做的事，尽量减少单页表单长度。
- 所有状态都区分“否”“未知”“未填写”。
- 路线的去程和回程分开显示，不能仅给一个平均分。
- 隐私设置用明确对象和内容描述，避免只显示含糊的“公开”开关。
- 最终参加确认与前期地点意向分开。
